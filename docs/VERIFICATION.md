# Проверка ХОД 0.25 · Caissa

Локально выполнено 5724 Java-утверждения: правила и perft, распознавание и границы доски, смена режима приложения, новая партия, Root-транспорт, Lichess/Cburnett, подсветка шаха, устойчивые координаты панели 263 проверки клиента Caissa и 349 проверок меток допустимых ходов.

В 0.25 отдельная регрессия сначала воспроизвела семь ложных белых пешек на присланной доске с выбранным конём. После фильтрации компактных полупрозрачных круглых меток все 64 клетки соответствуют законной позиции; шаблоны для этого теста взяты из другого, ранее присланного фото. Дополнительно проверены 7 цветовых палитр, оба положения доски, светлые/тёмные точки разных размеров и непрозрачностей, калибровка начальной доски с выбранной пешкой, снятие выделения, размеры 511/800/1264 с ненулевым экранным смещением, повторный автопоиск, сохранённая тема, отсутствие фиктивного хода при выборе и приём настоящего следующего хода. Настоящие непрозрачные фигуры на тех же клетках не стираются и не маскируют незаконные изменения позиции. Тесты создают маркеры в памяти; единственный новый файловый снимок содержит только доску без персонального интерфейса телефона.

В 0.23 регрессия с одним законным `bestmove` без `info pv` воспроизвела пользовательское исключение `Нет подтверждённого варианта для итогового хода Caissa`. В 0.24 этот ответ принимается после проверки законности, с отсутствующей оценкой/глубиной. Новые сценарии покрывают ответы без info, только с ограниченной оценкой или повреждённой строкой, другой итоговый ход после ранее опубликованного PV, оба цвета, продолжение тем же процессом, новую партию, мат в один, вынужденный ответ на шах, рокировку, en passant и превращение. Предыдущая оценка/вариант не переносятся; `0000` и `(none)` в позиции с законными ходами отклоняются.

UCI-проверки запускают отдельный асинхронный тестовый процесс. Проверяются идентификация Caissa, обязательные параметры, подтверждение загрузки сети по полному пути с пробелом, знаки оценок, авторитетный bestmove с собственной оценкой, полный исходный FEN/история, оба цвета, рокировки, en passant, превращение/недопревращение, шахи, мат/пат, отклонение незаконного итогового хода, отмена с запоздавшим bestmove и неблокирующее завершение, тайм-аут и замену процесса после отказа остановиться. Это не настоящий движок и не измерение силы.

В GitHub Actions дополнительно предусмотрена сборка настоящей Caissa 2.0 для Linux и прогон `CaissaNativeTest` через тот же Java-клиент. Он также проверяет реальные немедленные ответы Caissa без PV при единственном допустимом ходе за оба цвета. Этот шаг остаётся обязательным до сборки ARM64.

В среде подготовки нет Android SDK/NDK/CMake. Попытка загрузки исходников через настроенный proxy завершилась ошибкой соединения. Настоящая Caissa, Android-компиляция, APK, lint и испытания на realme здесь не запускались. Их нельзя считать пройденными по результатам тестового процесса. Замеры скорости телефона, игрового рейтинга и нагрева отсутствуют.

Сборка хранит неизменяемый commit Caissa 2.0, проверяет опубликованный GitHub хеш сети и записывает полные хеши бинарного файла и модели. Итоговый APK проверяется на ARM64, выравнивание ELF 16 KiB, отсутствие прежних движков и сетевого разрешения, соответствие постоянному сертификату. Ранний lint не отключён.

RootCaptureMain/Session/Wire, история, PanelPlacement и исправление клиента Caissa 0.24 сохранены. В 0.25 изменён только разбор графических точек в BoardVision; формат сохранённых шаблонов, общие пороги распознавания, проверки легальности, движок и параметры поиска не заменялись. Локальные данные моделей прежних версий и API-ключ удаляются при миграции; шахматная история и подпись сохраняются.

Также выполнены 7 Python-тестов сети/миграции/упаковки и 6 тестов постоянной подписи. Структурная APK-заглушка проверяет отбрасывание повреждённого движка/сети, старых библиотек, сетевого разрешения и прежнего API-класса; это не установленный или собранный Android APK. Синтаксически проверены 38 Java-файлов приложения, XML/YAML, Python и shell; настоящий native-тест скомпилирован, но не запущен из-за отсутствия бинарного движка.
